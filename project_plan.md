# Flutter App — Project Plan

Goal: a minimal Flutter app, for **Android** and **Windows**, that shows the live `count`
of one room stored in Firestore (`rooms/2OYdpmvifh2pjNl0WQu9`).

The app reads Firestore **directly** through the Flutter Firestore SDK. It does not call
the Cloud Function. The Cloud Function *writes* the count; the app only *watches* it.

```
 Door sensor ──POST /increment_count──► Cloud Function ──Increment()──► Firestore
                                                                          │
                                         Flutter app ◄──snapshots()───────┘
                                         (live listener)
```

## Step 1 — Create the Flutter project

Run this from the **repo root** (`C:\Documents\Door_sensor_project`):

```powershell
flutter create --platforms=android,windows --org io.github.andressalazaralturo --project-name door_sensor app
```

What each flag does:
- `--platforms=android,windows`: only generate the `android/` and `windows/` folders.
  Other platforms can be added later with `flutter create --platforms=web .`.
- `--org io.github.andressalazaralturo`: reverse-domain prefix. Combined with the project
  name, it becomes the Android **application ID**
  `io.github.andressalazaralturo.door_sensor`.
  - Android, Firebase and Google Play use this ID to identify the app. Once the app is
    published, the ID can never change; a new ID means a new app.
  - App IDs should start with a domain you own, written backwards. Without a personal
    domain, your GitHub Pages address (`andressalazaralturo.github.io`) is the usual
    choice.
  - It's all lowercase because that's the Android convention, and GitHub usernames aren't
    case-sensitive.
  - This is **not** your Firebase project ID. That's a separate ID, used in Step 3.
- `--project-name door_sensor`: the Dart package name. It must be lowercase with
  underscores. It's also the last part of the app ID.
- `app`: the folder to create.

> **Display name vs app ID:** by default the name shown under the app icon is the project
> name (`door_sensor`). That's just a label and can be changed any time: `android:label` in
> `android/app/src/main/AndroidManifest.xml` for Android, and the window title in
> `windows/runner/main.cpp` for Windows. Leave it for now.

**Look around** before changing anything:
- `app/lib/main.dart`: the demo "counter" app.
- `app/pubspec.yaml`: the project's manifest (name, SDK version, dependencies). It's
  similar to `requirements.txt`.
- `app/.gitignore`: Flutter adds its own ignore file (`build/`, `.dart_tool/`, …).

**Sanity check: run the untouched demo app on Windows** (before Firebase is involved):
```powershell
cd app
flutter run -d windows
```
- You should see the default counter app. Press `q` in the terminal to quit.
- *Why do this first:* if something breaks later, you'll know the base toolchain works and
  the problem is in the Firebase setup.

## Step 2 — Add the dependencies

From inside `app/`:
```powershell
flutter pub add firebase_core cloud_firestore
```

- `firebase_core`: connects the app to your Firebase project. Every other FlutterFire
  plugin needs it.
- `cloud_firestore`: the Firestore client SDK (reads, writes and live listeners).

Then check `pubspec.yaml`. Both packages now appear under `dependencies:` with a version
constraint like `^x.y.z`. `pubspec.lock` records the exact versions resolved. For an
*app*, you commit the lock file so every build uses the same versions.

> **Client SDK vs Admin SDK:** the Cloud Function uses the **Admin SDK**
> (`google-cloud-firestore`), which runs with server credentials and **ignores security
> rules**. The Flutter app uses the **client SDK**, which **is subject to security rules**.
> This matters in Step 5.

## Step 3 — Connect the app to Firebase

From inside `app/`:
```powershell
flutterfire configure --project=<your-project-id> --platforms=android,windows
```

What it does:
1. Registers an **Android app** in your Firebase project under the application ID from
   Step 1 (`io.github.andressalazaralturo.door_sensor`, read from
   `android/app/build.gradle.kts`). It also registers an app entry used for **Windows**.
2. Generates `lib/firebase_options.dart`, which contains `DefaultFirebaseOptions.currentPlatform`.
   That's the config (API key, project ID, app ID) for whichever platform the app is
   running on.
3. Generates `android/app/google-services.json` and adds the `google-services` Gradle
   plugin to the Android build.
4. Generates `firebase.json`, which records what was configured so it can be re-run.

Verify:
- Open `lib/firebase_options.dart` and confirm it has `android` and `windows` entries.
- In the Firebase console → Project settings → Your apps, you should see the new apps.

> **Is the API key a secret?** No. A Firebase API key identifies the project; it doesn't
> grant access. **Security rules** (Step 5) protect the data. Committing these generated
> files is normal.

## Step 4 — Write the app code

### 4.1 Replace `lib/main.dart`

```dart
import 'package:firebase_core/firebase_core.dart';
import 'package:flutter/material.dart';

import 'firebase_options.dart';
import 'room_count_page.dart';

Future<void> main() async {
  // Required before any `await` in main(): plugins talk to native code through
  // Flutter's engine binding, which isn't set up until this is called.
  WidgetsFlutterBinding.ensureInitialized();

  // Must finish before any Firestore call, otherwise you get "No Firebase App '[DEFAULT]'".
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );

  runApp(const DoorSensorApp());
}

class DoorSensorApp extends StatelessWidget {
  const DoorSensorApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Door Sensor',
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const RoomCountPage(),
    );
  }
}
```

### 4.2 Create `lib/room_count_page.dart`

```dart
import 'package:cloud_firestore/cloud_firestore.dart';
import 'package:flutter/material.dart';

// Hard-coded for now; later this could come from a room picker.
const String roomUid = '2OYdpmvifh2pjNl0WQu9';

class RoomCountPage extends StatefulWidget {
  const RoomCountPage({super.key});

  @override
  State<RoomCountPage> createState() => _RoomCountPageState();
}

class _RoomCountPageState extends State<RoomCountPage> {
  // Created once and kept in State. If it were created inside build(), every rebuild
  // would open a brand-new Firestore listener.
  final Stream<DocumentSnapshot<Map<String, dynamic>>> _roomStream =
      FirebaseFirestore.instance.collection('rooms').doc(roomUid).snapshots();

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Door Sensor')),
      body: Center(
        child: StreamBuilder<DocumentSnapshot<Map<String, dynamic>>>(
          stream: _roomStream,
          builder: (context, snapshot) {
            if (snapshot.hasError) {
              return Text('Error: ${snapshot.error}');
            }
            if (!snapshot.hasData) {
              return const CircularProgressIndicator();
            }

            final doc = snapshot.data!;
            // Like the API's 404: a missing document is not an error, just exists == false.
            if (!doc.exists) {
              return const Text('Room not found');
            }

            final count = doc.data()?['count'] ?? 0;
            return Column(
              mainAxisSize: MainAxisSize.min,
              children: [
                Text('Room $roomUid'),
                const SizedBox(height: 16),
                Text('$count', style: Theme.of(context).textTheme.displayLarge),
              ],
            );
          },
        ),
      ),
    );
  }
}
```

### 4.3 Remove the demo test

`test/widget_test.dart` tests the counter demo, which no longer exists, so
`flutter test` would fail. Delete it for now. Testing widgets that use Firestore requires
mocking Firebase, which is a later topic.

### Concepts in this code

- **Widget:** everything on screen is a widget. `build()` describes what the UI should
  look like right now.
- **StatelessWidget vs StatefulWidget:** a `StatefulWidget` has a `State` object that
  survives rebuilds. That's why the stream lives there.
- **`snapshots()`:** opens a **live listener**. Firestore sends the current document
  immediately, then sends it again every time it changes on the server.
- **`StreamBuilder`:** rebuilds its `builder` each time the stream emits a value. So when
  the Cloud Function increments `count`, the number on screen updates by itself.
- **`async main` / `await`:** Firebase setup is asynchronous (it may load native code and
  config), so the app only starts after it completes.

## Step 5 — Firestore security rules

The app reads without logging in, so the rules must allow **public read** on `rooms`.

1. Firebase console → Firestore Database → **Rules** tab.
2. **Look at the current rules first.** If the database was created in "test mode", it
   has an `allow read, write: if request.time < <date>` rule that silently expires. If it
   was created in "production mode", it denies everything.
3. Set the rules to:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rooms/{roomId} {
      allow read: if true;   // the app can read any room
      allow write: if false; // only the Cloud Function (Admin SDK) writes
    }
  }
}
```

4. Click **Publish**.

*Why `write: if false` doesn't break the Cloud Function:* the Admin SDK bypasses rules
entirely. Rules only apply to client SDKs, such as the Flutter app.

```powershell

```

- **The first build is slow** (it can take several minutes). `cloud_firestore` on Windows

- While it runs, these terminal keys are useful:
  - `r`: **hot reload**. Injects code changes and keeps the app's state.
  - `R`: **hot restart**. Restarts the app from `main()`.
  - `q`: quit.
- Try hot reload: change the AppBar title, save, press `r`.

> FlutterFire's Windows support is officially intended for **development**, not
> production releases. That's fine for this project.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `Building with plugins requires symlink support` | Windows Developer Mode is off (Step 0.2) |
| `No Firebase App '[DEFAULT]' has been created` | `Firebase.initializeApp()` missing or not awaited in `main()` |
| `[cloud_firestore/permission-denied]` | Security rules don't allow the read (Step 5) |
| Shows "Room not found" | UID typo, or the document is in a different Firebase project than the one used in `flutterfire configure` |
| Count shows but never changes | The function is writing to a different project/document; check the API response's `room_uid` |
| Android `minSdk` build error | Raise `minSdk` in `android/app/build.gradle.kts` (Step 7.2) |
| `flutterfire` not recognized | `dart pub global activate flutterfire_cli`, and make sure `%LOCALAPPDATA%\Pub\Cache\bin` is on PATH |
| Windows build very slow the first time | Expected: Firebase C++ SDK download (Step 6) |
